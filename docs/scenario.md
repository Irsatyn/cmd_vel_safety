# 测试场景标注与实测结果

本文件逐段标注给定 rosbag（`src/cmd_vel_safety/bags/cmd_vel`）的内容，并给出
系统的**实测**响应。表中的输出数值取自实际运行录制的
`/velocity_guard/report`，不是预期值。

## 1. 输入数据概况

| 项 | 值 |
|---|---|
| Topic | `/cmd_vel` |
| 类型 | `geometry_msgs/msg/Twist` |
| 消息数 | 320 |
| 时长 | 35.9 s |
| 发布频率 | 10 Hz（相邻间隔 100 ms，仅一处例外） |

## 2. 逐段标注与实测响应

控制器以 20 Hz 输出，下表 `out_v / out_w` 为该段**稳定后**的输出值。

| 帧号 | t (s) | 输入 | 测试意图 | 实测 target | 实测 output | 置位的 flags |
|---|---|---|---|---|---|---|
| 0–29 | 0.0–2.9 | 全零 | 静止 | 0, 0 | 0, 0 | — |
| 30–80 | 3.0–8.0 | `lx=0.3` | 正常匀速 | 0.300, 0 | 0.300, 0 | `ACCEL`（仅起步 0.35 s） |
| 81–119 | 8.1–11.9 | `lx` 斜坡 0.3→0.8 | 平滑加速不得失真 | 跟随 | **逐帧完全跟随** | — |
| 120–159 | 12.0–15.9 | `lx=0.5, az=0.6` | 弧线 + 阶跃入口 | 0.500, 0.600 | 0.500, 0.600 | `ACCEL`（0.3 s 过渡） |
| 160–189 | 16.0–18.9 | `lx=-0.35` | 倒车，反向限幅更严 | **-0.300**, 0 | -0.300, 0 | `SPIKE`(1帧) → `LIN_CLAMP` |
| 190–219 | 19.0–21.9 | `lx=2.5, az=3.0` | 持续超限 | **1.000, 1.200** | 1.000, 1.200 | `SPIKE`(1帧) → `LIN_CLAMP`,`ANG_CLAMP`,`LAT_ACC` |
| 220 | 22.0 | `lx=NaN` | 非法数值 | 保持 1.000, 1.200 | **不受影响** | `NON_FINITE` |
| 225 | 22.5 | `az=+Inf` | 非法数值 | 保持 0.250, -0.250 | **不受影响** | `NON_FINITE` |
| 230 | 23.0 | `lx=-2.2`（单帧） | 孤立毛刺 | 保持 0.250 | **0.250（毛刺未进入输出）** | `SPIKE` |
| 240–279 | 24.0–27.9 | `lx=0.3, ly=0.4` | 非完整约束违例 | 0.300, **0** | 0.300, 0 | `NONHOLO` |
| — | 27.9→32.0 | **4.1 s 空洞** | 指令中断 | **强制 0, 0** | 0.300→0.151→0.000 | `WATCHDOG`,`ACCEL` |
| 280–314 | 32.0–35.4 | `lx=0.2` | 恢复，不得跳回旧速 | 0.200, 0 | **0.040→0.200 渐升** | `ACCEL` |
| 315–319 | 35.5–35.9 | 全零 | 停车 | 0, 0 | 0.125→0.000 | `ACCEL` |

### 几个值得单独说明的实测结果

**第 190–219 段的角速度被压到 1.200，而不是限幅上限 1.500。**
两级限幅串联生效：`az=3.0` 先被 `max_angular_z=1.5` 限到 1.5，随后向心加速度
约束 `|v·ω| ≤ 1.2` 在 `v=1.0` 时把 ω 进一步压到 1.2。单独看任何一个限幅参数都
解释不了这个数值，这正是 §6.4 引入耦合限幅的理由。

**第 160 帧与第 190 帧都先置 `SPIKE` 一帧，然后被采纳。**
这是「候选—确认」机制的预期代价：真实阶跃指令延迟一个输入周期（100 ms）。
由于斜率限幅本身就要用 0.4–1.5 s 完成这类速度变化，这 100 ms 在输出曲线上不
可见。

**第 230 帧的毛刺在输出上完全不可见。**
`target` 与 `output` 在 23.0–23.1 s 期间始终为 `0.250 / -0.250`，与毛刺前后完全
一致。这是第 230 帧与第 190 帧必须被区别对待的核心证据。

**第 220 / 225 帧的非法值未触发安全保持。**
`max_consecutive_invalid=5`，而 bag 中的非法帧是孤立的（连续计数最多为 1），
因此系统容忍并跨过，不中断运动。持续非法的情形见 §4。

**空洞结束时输出是 2 个周期的斜坡，不是单步跳零。**
实测 `0.300 → 0.151 → 0.000`，对应 `max_linear_decel × emergency_decel_factor
= 3.0 m/s²`。离线校验脚本会断言这一点（见 §5）。

**恢复后输出从 0.040 起步爬升到 0.200，而非跳回中断前的 0.300。**
看门狗触发时把 `target_` 重置为零，使恢复后的首帧指令相对静止被评估。

## 3. 计数器自证

一次完整回放后 `/velocity_guard/report` 的累计计数器：

| 字段 | 实测值 | 核对 |
|---|---|---|
| `total_received` | 320 | 与 bag 的 `message_count` 完全一致 |
| `total_rejected` | 6 | 2 帧非法数值（220、225）+ 4 帧待确认跳变（160、190、221、230） |
| `total_modified` | 40 | 第 240–279 帧，恰为 `ly=0.4` 的 40 帧 |
| `total_published` | 719 | 20 Hz × ≈36 s 回放 |

## 4. bag 未覆盖的规则

给定 bag 不含死区、持续非法输入与急停场景，这三条规则由独立的在线测试覆盖
（见 README 的「验证」一节），实测结果：

| 场景 | 输入 | 实测输出 | 置位的 flags |
|---|---|---|---|
| 死区 | `lx=0.005` 持续 | `0.0000` | `DEADBAND` |
| 持续非法 | `lx=NaN` 持续 3 s | `0.0000`，受控停车 | `NON_FINITE`,`HOLD` |
| 非法恢复 | 恢复 `lx=0.5` | 爬升回 `0.5000` | `ACCEL` |
| 急停生效 | `/e_stop=true`，仍指令 0.5 | `0.0000`，latched | `ESTOP` |
| 急停解除 | `/e_stop=false`，仍指令 0.5 | 从 0 重新爬升 | `ACCEL` |

11 条安全规则至此全部被实测覆盖（bag 覆盖 8 条 + 上表 3 条）。

## 6. 关于 `flags` 字段的采样语义

`flags` 描述的是**该控制周期内发生了什么**，而不是「当前输入是否仍然违规」。
输入 10 Hz、输出 20 Hz，因此与输入校验相关的位（`NON_FINITE`、`NONHOLO`、
`SPIKE`、`DEADBAND`）只会在收到新帧的那一半周期里置位，在 `rqt_plot` 上呈现为
方波。与输出级相关的位（各类 `CLAMP`、`ACCEL`、`WATCHDOG`、`ESTOP`）在条件
持续期间每周期都置位。

这是刻意的：逐周期语义使「哪一帧触发了哪条规则」可精确定位。若需要判断「当前
输入是否仍然违规」，应读同一条消息里的 `input_cmd` 字段，它始终保存最近一次
原始输入。
